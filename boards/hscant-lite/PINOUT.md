# HSCanT-Lite Pin Assignment

HPM5321 / HPM5361, QFN48. This table is the reference for the shared
`boards/hscant-lite` package used by candleLight,
[`hpm_dfu_boot`](https://github.com/zhangjiance/hpm_dfu_boot.git) and
hpm_hello_world.

> The original `hscant-lite.hpmpc` was removed because it no longer passes the
> HPM Pinmux Tool server validation (error 30003, "The file is damaged!").
> Recreate the tool project from this document if interactive editing is
> needed.

## CAN (MCAN)

| Controller | Signal | MCU pin |
| --- | --- | --- |
| MCAN0 | TXD | PA00 |
| MCAN0 | RXD | PA01 |
| MCAN1 | TXD | PA05 |
| MCAN1 | RXD | PA04 |
| MCAN2 | TXD | PA08 |
| MCAN2 | RXD | PA09 |
| MCAN3 | TXD | PA31 |
| MCAN3 | RXD | PA30 |

The CAN pin muxing is identical to HSCanT.

## LEDs

Eight discrete LEDs, grouped by net parity. The two groups have opposite
polarity.

| Net | MCU pin | Color | Polarity | Functional use |
| --- | --- | --- | --- | --- |
| LED0 | PA02 | red | active high | CAN0 error |
| LED1 | PA26 | white | active low | CAN0 status |
| LED2 | PA27 | red | active high | CAN1 error |
| LED3 | PA28 | white | active low | CAN1 status |
| LED4 | PA10 | red | active high | CAN2 error |
| LED5 | PB10 | white | active low | CAN2 status |
| LED6 | PB09 | red | active high | CAN3 error |
| LED7 | PB08 | white | active low | CAN3 status |

Wiring:

- Red / even nets: GPIO -> LED -> 2.2 kOhm -> GND. Drive 1 to light.
- White / odd nets: GPIO <- LED <- 2.2 kOhm <- 3V3. Drive 0 to light.

### LED behavior

**candleLight**

- White status LED: on while the channel is started; a short dark pulse on
  TX/RX activity.
- Red error LED: blinks while a bus error is latched; off otherwise.

**hpm_hello_world**

- `board_led_toggle()` walks all eight LEDs one at a time, alternating
  white/red:
  LED1 -> LED0 -> LED3 -> LED2 -> LED5 -> LED4 -> LED7 -> LED6.

**[hpm_dfu_boot](https://github.com/zhangjiance/hpm_dfu_boot.git)**

- No blinking. The generic boot LED hooks only set the initial and deinit
  state; they are not polled.

## Pinmux source note

`pinmux.c` still uses the legacy net-label aliases generated by the HPM Pinmux
Tool (`CAN0_TR`, `CAN0_STA`, ...). Those names do not describe the functional
role on this board. The authoritative status/error mapping is the table above
and the `s_chan_status_led` / `s_chan_error_led` tables in `board.c`.
